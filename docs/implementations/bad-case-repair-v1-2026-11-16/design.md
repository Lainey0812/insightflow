# Bad Case归因与修复回流设计

保持既有追加式BadCase与事件表。新增in_progress、pending_verification状态，open显示待处理；历史confirmed/fixed/wont_fix/invalid不改写。新增归因事件，保留操作者、原因、节点、说明。序号CAS继续保护并发。

列表内联归因，详情复用同一表单。提交归因才进入处理中，前端选择不写状态。Prompt修复显式选择真实LLM节点，疑似归因不是事实诊断。详情立即修复同标签导航到Prompt工作台，query只携带BadCase ID与节点；编辑卡片读取服务器归因确认上下文。

底部确认保存不可变System草稿，再追加修复提交事件进入待验证并导航回原BadCase详情。跨库非事务：先草稿、后事件，事件失败则留在编辑页，不伪称完成，可能留下可追溯孤立草稿；重试保存相同内容幂等。服务器核对case状态、归因、目标节点、版本类型和序号。仅提交草稿，不发布生产Prompt、不执行LLM、不自动验证成功。

界面沿用蓝白管理台：密集表格展示问题与当前归因；行内编辑区与详情区使用同一控件。Prompt顶部修复来源条与底部确认栏是显式业务上下文，不增加装饰卡片。其他原因跳到对应现有Workflow证据/诊断节点；不假装有代码或数据编辑器。旧状态操作继续兼容，新状态只能通过新命令进入。
