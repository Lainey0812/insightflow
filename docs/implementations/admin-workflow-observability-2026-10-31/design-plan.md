# Admin Workflow Observability V1 设计计划

目标读者是功能测试和故障诊断人员。沿用现有 Admin 视觉系统，不改成统计 Dashboard，也不引入新的 UI 框架。

色彩：背景 #F6F5F8，表面 #FFFFFF，正文 #292737，关联操作 #7360B3，成功 #32735A，异常 #A54858。字体沿用 PingFang SC / 系统无衬线，业务标签与正文保持正常比例，只有不透明 ID 使用等宽字体方便核对。

列表采用紧凑可扫描表格；详情按“业务状态与来源、真实关联、实际节点时间线、观测边界”分区。时间线的纵轴用于实际开始时间，而非预设阶段占位；节点可展开原始事件和已采集调用。同一 node_key 的重入保留独立 node_attempt。

结构：

列表：标题与只读提示 / 精确ID与业务状态筛选 / 表格 / 分页。
详情：返回与手动刷新 / 业务生命周期摘要 / 关联链 / 实际Span时间线 / 采集缺口与未执行决策。

方案复核：没有采用 KPI 卡片、模拟成功率或装饰性指标。业务完成状态来自既有 Lifecycle 的业务库投影；Trace 仅决定采集与诊断显示。保留 Trace/Prompt 两个已开放导航组，新入口放在“运行追踪”下，其他模块仍灰色。保持老 C2 Trace API 契约不变；新增最小只读 observability view 接口，内部复用 C2 service 和既有 Lifecycle aggregate，而非新建事实来源。
