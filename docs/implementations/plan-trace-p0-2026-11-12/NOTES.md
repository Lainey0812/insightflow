# plan-trace-p0

REQ-0136。把每一次计划校验、人工审批和执行结果关联到当时保存的计划版本，并让洞察生成对照已保存的模型请求。

修改前副本在本目录 `before/`。历史需求、快照和评测没有覆盖。

读取侧：

- 新产生的计划校验 span 写入计划编号和计划版本。已经落库的历史 span 不回填。
- 校验节点优先使用 span 上的计划版本。历史记录没有该字段时：规划返回使用当时的规划结果；初次保存使用唯一一条创建记录；审批期间使用时间窗口内唯一一条人工审核记录上的计划版本。对不上就不挂计划正文。
- 版本对照同时给出被校验的版本、批准快照里的版本、执行记录里的版本。同一计划编号下执行版本不止一个时标成不止一个执行版本。
- 人工审核展示提交审批时的计划正文。只有审批编号与批准快照一致时，才展示批准正文。
- 分析执行按任务展示字段、过滤条件、分组维度和聚合方式，并附上当时保存的结果，最多 8 列、20 行。这是已保存结果，不是重新计算。任务对象不使用 `rows` 字段。
- 洞察生成的 Input 只展示该次已保存请求中的分析目标、用户约束、样本计数和证据值。请求过期或读不出时不从当前报告重建。`source_row_indices` 不展示。

真实流程 `wf_d37a472ad4de4d28b5c2df9646c84914`：三次计划校验都能看到计划正文。被校验版本、用户批准版本、执行版本一致。人工审核能看到提交正文和批准正文。分析执行 4 个任务能看到计算规则和结果表。洞察生成 Input 能看到业务目标、用户约束和证据值，LLM 页仍在。右侧详情约 501px。页面上没有批准按钮。

验证：Admin 类型检查通过；workflows、failure-diagnosis、quality-signals 共 23 项通过；生产构建通过。后端工作流详情测试通过，校验投影绑定了计划正文，执行任务带有规则且没有 `rows`。

仍保留的边界：历史校验 span 依赖人工审核的时间窗口；过期或未保留的模型请求继续显示未采集；结果预览有 20 行、8 列上限。计划校验、审批、执行和洞察生成的业务判定没有改。
