# 分析方法改进第一阶段：执行样本与统计口径

本需求授权按审计顺序开始实施。本次增量先完成第一阶段可验证的数据基础，不将后续图表方向、方法库、解释生成或自然语言修订混入同一变更。

## 来源与边界

在 Analysis Engine 已批准任务的聚合输入视图计算统计，使用现有解析、规范化、筛选和派生规则；不在 Report 端重放操作、不读取任意客户端路径、不改统计内核。统计随原 ExecutionResult 原子持久化，沿用原审批与版本绑定。

仅对恰好一个聚合步骤的任务提供联合样本统计；无聚合、多次聚合或执行失败时不宣称原始记录联合统计已存在。关键字段明确限定为该聚合的分组字段与非空 metric.field 的并集；不冒充业务确认的主键或业务实体。派生字段引用保留真实别名及显示名称。

统计边界为聚合前输入，而不是 Top N 后的返回分组来源记录。联合缺失数按行去重，完整数与缺失数之和等于聚合前行数。缺失分组仍可能被保留，缺失指标仍按现有各函数规则处理，不因统计新增而自动剔除记录。

没有字段依赖的 count() 不虚构关键字段完整/缺失数，显示不适用。所有指标另存输入字段、函数、参与非空数和计数依据；count() 是行数，count(field) 是非空数，distinct_count(field) 是非空去重值数。

## 展示与兼容

TaskExecutionMetadata 新增默认 None 的可选样本统计，旧记录可继续解析。新报告沿用原执行 metadata 复制，无需改写 AnalysisReport 或历史载荷。单方向可显示四卡；多方向分别展示，不因数字相同推断范围相同。HTML 与页面共用同一保存事实。

业务实体粒度、币种、税费、退款范围未确认；只解释当前真实函数，不将行数改称订单数或自动选择业务口径。原始 API Key、明细行、缺失行集合不加入报告；仅保存计数和字段引用。

## 验收

用包含交叉缺失、重复业务编号、筛选、Top N、空结果、派生及多方向的 CSV 测试。比较独立 Pandas 行掩码，验证不是列缺失数相加。核对 count/count(field)/distinct_count、持久化重读、历史 None、无字段 count() 与不支持链路。保持原计算结果、审批防护、Workflow/Trace 行为不变。
