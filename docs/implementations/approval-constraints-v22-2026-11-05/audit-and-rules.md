# 审批误阻断根因与修复规则

REQ-0093，2026-11-05。本次只处理正常需求与真实操作之间的确定性映射，不调整LLM Prompt正文、模型参数、Engine算法或审批/执行版本绑定。

## 已复现的四个原因

- U02：Intent保留“按团队计算”。旧语法只接受分组/汇总/统计/比较/分析，未接受计算，尽管实际group_aggregate已按唯一真实团队字段分组。
- W03：排序写“按平均值降序排列”，旧逻辑要求字段名，无法使用唯一已规划avg指标。同时“不要推断人员绩效”是报告表达边界，旧逻辑错误要求它映射数据字段。
- W04：清理前缀时正则把短的“仅”放在“仅分析”之前，剩下“分析已完成任务”，无法对应真实“已完成”状态值。另外没有任务编号时旧实体计数词表拒绝“任务数量”，虽然用户明确分析任务且计划为逐行count。
- T04：没有利润字段被当作禁止利润要求无法验证；“也不要推断团队差异的原因”没有区别于执行过滤条件。

上轮真实失败记录和修复后的逐条proof保存在评测目录saved-blockers-replay.json。未改写原始Intent、原审批记录、旧计划或任何历史数据库。

## 确定性映射边界

### 执行条件

按“真实唯一字段计算”与分组同义，但仍需真实group_aggregate。字段省略的“平均值/中位数/总和排序”只绑定实际唯一同函数聚合指标；多个候选拒绝。排序仍须是聚合后真实操作，方向必须一致。

前缀按完整表达先匹配；状态值仍由完整、未截断且唯一字段样本绑定。未知值、不完整样本、跨字段同值和错误范围仍阻断；不能使用当前过滤结果碰巧相同作为证明。

实体数量按上传记录计数。仅当实际标识字段或已保存明确分析对象提供实体上下文时支持；存在“任务数量”等真实数量列时仍拒绝擅自改为行数。计划展示新增“按上传记录逐行计数，不代表去重后的业务实体数量”。非空计数、去重计数及sum不得冒充逐行count。无法确定去重实体口径时仍需要重新明确需求。

### 报告边界

新增有限词典output_boundaries，识别明确的禁止原因/绩效推断和禁止利润分析表达，不做通用自然语言推断。proof记录为enforced_report_boundary，明确标注policy_version与boundary，不伪造字段或操作参数。

原因/绩效边界以当前受控Report V2为必要条件；报告运行时再次校验生成版本，不支持的版本明确失败。报告使用受控摘要/图表标题，建议限来源与已有缺失核查，不能通过自由任务标题或新增分析方向绕开边界。

禁止利润通过实际字段引用、别名和已支持操作的缺席验证；利润/盈利/毛利/净利/profit/margin字段或别名参与时不批准。未知操作/派生也不作能力缺席证明。这是有限受控词汇，不声称识别一切隐藏业务语义。未列明边界继续unmapped；“不要求”“未指定”不升级为禁止或必选。
