# InsightFlow — 第一阶段工程框架搭建

## 1. 项目背景

InsightFlow 是一个面向普通业务人员的 AI 数据分析 Web 应用。

产品目标：让不具备专业数据分析能力的用户，通过上传数据和描述业务目标，获得专业、可验证的数据分析结果、可视化图表和业务洞察。

## 2. MVP 核心流程

用户上传 Excel/CSV 并输入分析需求 → Intent Parser 理解目标 → Data Profiler 生成数据画像 → Analysis Planner 生成分析计划 → HITL 用户确认或修改 → Analysis Engine 执行分析 → Report Module 生成图表、结论和数据依据。

Intent Parser 与 Data Profiler 可以独立执行，Analysis Planner 必须等待两者所需信息准备完成。

## 3. MVP 功能范围

- 支持单个 Excel/CSV 文件上传。
- 支持自然语言分析目标。
- 支持目标驱动和探索式分析。
- 支持 AI 生成分析任务。
- HITL 支持确认、删除任务、通过自然语言要求 AI 修改。
- 支持确定性统计计算。
- 支持图表、结论和数据依据展示。
- 暂不支持外部数据抓取、多用户协作、复杂语义派生和多 Agent 自由协作。

## 4. 推荐技术栈

- Frontend：React、TypeScript、Vite、ECharts
- Backend：Python、FastAPI
- Data：Pandas
- Storage：SQLite + 本地文件存储
- AI：可替换的 LLM Provider 接口
- Workflow：代码实现的受控状态机

如发现已有项目基础，请先检查现有结构，避免重复初始化或覆盖文件。

## 5. 模块划分

- Intent Parser：需求理解、分析模式识别、歧义管理。
- Data Profiler：文件解析、字段识别、数据质量检查。
- Analysis Planner：分析任务规划、优先级和可行性判断。
- HITL：计划审核、删除、AI 修订、版本确认。
- Analysis Engine：执行受控统计操作并产生 ExecutionResult。
- Report Module：生成有数据依据的洞察与 ECharts 图表配置。
- Workflow Orchestrator：状态流转、节点调度、暂停和恢复。

上述模块为逻辑模块，不要求拆分成独立微服务。

## 6. 第一阶段开发任务

本阶段只搭建工程骨架，不实现完整 AI 业务逻辑。

1. 初始化前后端工程。
2. 建立清晰的模块目录和基础依赖。
3. 创建健康检查及必要的占位 API。
4. 定义最小 Session State 和状态枚举。
5. 建立统一的节点输入、输出和错误处理约定。
6. 建立 LLM Provider 抽象接口，但暂不调用真实模型。
7. 使用 Mock 节点模拟流程流转。
8. 建立前端基本页面：数据输入、计划审核、分析报告。
9. 编写最小自动化测试和本地运行说明。

## 7. 重要工程约束

- 不允许 LLM 直接生成统计结果作为真实计算结果。
- AI 规划与确定性计算必须解耦。
- HITL 未批准计划前不得执行分析。
- 计划修改应保留版本。
- 不引入不必要的微服务、多 Agent 框架和复杂基础设施。
- Mock 数据和真实数据必须明确区分。
- 所有核心模块应便于后续逐步替换和扩展。

## 8. 第一阶段验收标准

- 前后端能够正常启动。
- 前端能够调用后端健康检查接口。
- 用户能够进入输入、计划审核、报告三个基本界面。
- Mock Workflow 能够演示从提交到等待确认，再到完成的状态变化。
- 项目目录清晰，核心模块之间不存在不必要的循环依赖。
- 自动化测试通过。
- 提供 README，说明安装、启动、测试及下一阶段开发方式。
