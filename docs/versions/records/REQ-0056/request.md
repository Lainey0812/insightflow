# InsightFlow Trace V0.3 — 真实工作流接入审计

## 目标

确保 Admin Trace 展示的是 InsightFlow 前台真实数据分析任务的执行过程，支持运行中监控和历史追溯。

## 审计要求

1. 从前台上传数据、用户输入分析需求开始，追踪实际后端调用链。
2. 识别 Understanding、Planning、Execution、Reporting 的真实执行入口。
3. 确认一次分析任务能否关联统一根 Run ID。
4. 检查 HITL 审批、Intent 澄清和恢复执行是否保留关联。
5. 检查所有节点是否在开始、结束、失败时持久化真实事件。
6. 检查 LLM 重试是否保留独立 Attempt。
7. 检查 Report Trace 与 Prompt Registry 的关联。
8. 检查实时运行状态、异常退出和历史查询的真实性。
9. 标记没有真实埋点的节点，禁止前端伪造成功状态。
10. 不修改现有业务逻辑和 Prompt 内容。

## 交付要求

输出：

- 前台到后端的真实执行链路。
- 四阶段各节点的埋点覆盖表。
- 当前 Run ID 关联情况。
- 实时与历史 Trace 的数据缺口。
- 最小改造方案和测试计划。

先完成审计，不直接开发 UI。

## 验收原则

使用真实前台数据分析任务触发运行。

Admin 必须能根据真实持久化事件展示执行进度。

没有真实执行证据的节点不能标记为成功。

不得使用 Mock、固定延迟、前端推测状态或最终报告反推节点完成状态。
