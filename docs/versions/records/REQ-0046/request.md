# InsightFlow Admin — Trace V0.3 版本追溯与运行对比

## 目标

基于已经完成的 Trace V0.1 和 V0.2，增加历史版本追溯和两次运行对比能力。

本轮不开发完整 Evaluation Center。

## 第一阶段：审计

检查现有 RunManifest、TraceSpan、TraceEvent、Admin API 和快照持久化能力。

确认哪些版本字段在运行时真实采集，哪些只是静态配置或尚未采集。

## 第二阶段：版本追溯

- 在 Run 详情展示不可变 RunManifest。
- 记录真实 Git Commit、Prompt 版本、模型及参数、校验器版本。
- 记录数据集和关键输入快照的哈希或受控引用。
- 对缺失字段明确标记 unknown。
- 不允许用当前配置填补历史版本。

## 第三阶段：Run Comparison

- 支持选择两个历史 Run。
- 对比整体状态、节点状态、耗时、错误。
- 对比已保存的 Evidence、LLM 输出及报告。
- 支持按稳定的节点身份和重试序号匹配 Span，不只依赖列表顺序。
- 提供原始 Trace 跳转入口。

## 第四阶段：可比性检查

对比数据集、用户分析目标、审批计划、执行结果、模型配置和版本信息。

输出：

- comparable：关键输入和对比范围已验证一致。
- partially_comparable：部分条件一致，存在明确差异。
- unknown：缺少足够快照，无法判断。

不得将“输入相似”当作“输入相同”，不得直接将运行差异解释为某个 Prompt 改动造成。

## 第五阶段：验收

至少验证：

1. 历史 Run 能读取真实版本信息。
2. 两次运行能够正确对齐 Span。
3. 不同输入会被识别为不可直接比较。
4. 缺失版本信息不会被伪造。
5. 不同错误规则和报告状态能够正确显示。
6. 页面刷新后对比结果可恢复。
7. 既有 Trace API、Admin 页面及后端测试不退化。

交付修改清单、真实运行对比示例、测试结果与已知限制。

保持现有业务工作流不变，不新增 LLM 节点。
