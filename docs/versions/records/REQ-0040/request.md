# InsightFlow — Insight Generator V1.1.1 生成可靠性修复

## 目标

修复 V1.1 真实评测中暴露的生成可用率退化问题。

保持已经实现的多证据综合、确定性比较计算、统一报告来源和证据追溯能力。

本轮不以增加洞察深度为主要目标。

## 第一阶段：失败归因

对 V1.1 的 7 个不可用案例逐一建立失败记录。

每条记录必须包含：

- 用户分析目标。
- Evidence 输入。
- LLM 原始候选。
- 候选引用的证据。
- 触发的校验规则。
- 拒绝原因。
- 是否属于误拦截。
- 是否存在真实无依据断言。
- 是否存在跨指标或跨范围混引。
- 是否可以通过确定性规则修复。

将失败分类为：

A. 模型生成错误。

B. 校验误拦截。

C. 证据组合不合法。

D. 后处理或报告组装错误。

E. 其他。

不要把所有失败简单归因为 Prompt。

## 第二阶段：修复校验

1. 对数值、指标、排名、差值、比例实施结构化校验。
2. 明确区分肯定断言、否定性边界提示和待验证假设。
3. 对跨指标、跨任务、跨统计范围的证据组合进行兼容性验证。
4. 不通过直接删除正则或关闭校验提高可用率。
5. 对可安全修复的表达，使用确定性改写。
6. 无法验证的事实性断言仍应拒绝。
7. 当部分候选被拒绝时，保留合法候选并标记 partial。
8. 当核心业务目标没有任何有效洞察时，不得将空洞报告标记为完整成功。

## 第三阶段：优化事实表达

保持现有公开 AnalysisReport Schema。

明确 fact、finding、implication、recommendation 的职责。

消除页面和 HTML 中的重复事实表达。

确保所有面向用户的数值均能追溯到 Evidence。

## 第四阶段：回归验证

重新运行冻结的 15 个可生成案例，以及无有效证据案例。

另增加针对以下边界的单元测试：

- 合法否定性提示。
- 无依据利润断言。
- 无依据因果断言。
- 跨指标混引。
- 不同时间范围比较。
- Top N 与总体占比混淆。
- 多证据合法比较。
- 部分候选被拒绝。
- 重复事实展示。

要求：

- 不降低事实准确性和安全边界。
- 不通过减少合法校验来虚增成功率。
- 与旧版、新版 V1.1 使用相同的可用性定义。
- 同时报告完整成功、部分成功、失败数量。
- 单独报告独立未见集，不因总量较小而掩盖退化。
- 提供真实模型调用及 A–G 业务质量评测。

## 交付

先提交失败归因表及修复方案，再实施修改。

修复后提交：

1. 修改文件及原因。
2. 校验规则前后对比。
3. 15 个案例逐例结果。
4. 真实模型输出与保存报告。
5. A–G 业务质量评分。
6. 仍然失败的案例和原因。
7. 是否达到 V1.1.1 验收条件。

不得仅以自动化测试通过作为业务验收依据。
