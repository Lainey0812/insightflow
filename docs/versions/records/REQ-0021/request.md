# InsightFlow — Intent Parser V1.3 语义可靠性优化

## 目标

基于 V1.2 的真实评测结果，修复高风险语义错误，提高约束分类一致性。

保持现有模型、IntentResult Schema 和单 LLM 节点架构。

## 任务一：否定语义专项优化

在 Prompt 中明确区分：

- required：用户明确要求。
- unspecified：用户未指定。
- optional：用户表示非必选。
- prohibited：用户明确禁止。

以上是内部语义判断规则，不要求新增输出字段。

重点防止：

1. 将“不要求”升级为“禁止”。
2. 将“未指定”升级为“要求”。
3. 将“不要”弱化为“可选”。
4. 在 business_goal 中增加用户明确未要求的分析目标。

对 N07、N10、N11 建立固定回归测试。

## 任务二：范围提取一致性

明确区分：

- 分析对象。
- 数据筛选范围。
- 缺失的筛选条件。
- 明确的排除条件。

要求保留用户明确指定的有效分析范围。

如果筛选对象不明确，应保留已知信息，并将缺失部分记录为 uncertainty。

不得为了满足原话校验而拼接不存在的连续文本。

## 任务三：约束分类与最小完整片段

为四类约束建立清晰分类规则。

要求：

- 指标保留完整业务名称。
- 排序和 Top N 进入 analysis_limits。
- 时间进入 time_range。
- 数据子集进入 filters。
- 禁止性分析边界进入 analysis_limits。
- 不把无独立意义的“比较”提取为约束。
- 不跨类别复制包含多个约束的完整长句。

允许必要的指标上下文出现在排序限制中。

## 任务四：修复 C07 原话校验问题

检查当前 grounding 校验是否错误要求所有语义表达必须是连续原文子串。

优先让 Prompt 输出真实连续原话片段。

对模型生成的解释性文本与必须严格溯源的约束字段分别制定校验规则。

不能为了通过校验而接受不存在于用户输入中的虚构筛选值。

## 任务五：评测器优化

先冻结新的评分规则，再重评已保存的 V1.1、V1.2 输出。

重点修复：

- 排序限制包含指标上下文时的误报。
- 合法语义等价片段的误报。
- 否定表达仅在 business_goal 中发生错误时的漏报。
- 重复约束、跨类别混合和无意义约束的识别。

保留原始评分结果，不覆盖历史记录。

评测规则不得因为本轮模型输出而进行针对性放宽。

## 任务六：真实模型回归

使用：

- 原有 40 条回归样本。
- V1.2 的 28 条样本。
- 新增独立未见测试集。
- 否定语义专项样本。
- 多约束组合专项样本。

记录：

- 模型和 Prompt 版本。
- Schema 版本。
- 调用成功率。
- 约束召回率与精确率。
- 完整请求通过率。
- 否定语义错误数。
- 所有剩余 Bad Case。

## 验收要求

不得以单项召回率达到 95% 宣称通过。

重点要求：

- 不出现否定语义反转。
- 不出现凭空增加的核心分析目标。
- 显式约束召回率 ≥95%。
- 约束精确率 ≥95%。
- 阻断性问题识别不退化。
- 真实 LLM 返回失败不被 Mock 掩盖。

在独立未见样本中完成验证，且需要人工复核关键语义案例。

不要修改 Analysis Planner、HITL、Engine 或 Report 的业务实现。
