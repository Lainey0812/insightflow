下一步我们进入 InsightFlow 需求保真评测。

重点验证：用户原始需求中的目标和约束，能否经过 Intent Parser、Analysis Planner、Plan Validator，最终准确落实到 Analysis Engine。

先定义评测标准和失败类型，再设计测试用例，不急着修改代码。




我们下一步先定义 需求保真评测标准，重点检查三个环节：
1. Intent Parser：是否正确识别用户的分析目标、筛选条件和排除条件。
2. Analysis Planner：是否完整继承这些约束，并落实到具体分析任务。
3. Analysis Engine：实际执行的过滤条件和计算规则是否与用户需求一致。
我建议采用 端到端评测为主、节点级诊断为辅 的方式。

例如用户要求「对比上海和深圳的岗位数量，排除实习岗位」，只有最终计算确实排除了实习岗位，才算端到端需求保真通过。
