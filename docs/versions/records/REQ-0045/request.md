# InsightFlow Admin — Trace V0.2

## 目标

基于已完成的 Trace V0.1 后端基础设施，开发可用于真实问题诊断的 Admin Console。

本轮不重新设计 Trace 数据模型，不创建第二套运行记录。

## 第一阶段：审计现有能力

检查 V0.1 已实现的 Run、Span、Event、RunManifest 模型与 Admin API。

确认：

- 可查询字段与状态定义。
- Span 父子关系与重试记录。
- 错误代码和诊断信息的保存方式。
- 输入输出快照是否可读取，以及权限和脱敏限制。
- 现有 Admin 前端结构。

列出缺失字段及最小兼容调整方案。

## 第二阶段：Run Explorer

开发 `/traces` 页面。

要求支持：

- 真实运行列表。
- 状态、时间、节点、版本过滤。
- 分页和加载状态。
- 空数据、请求失败状态。
- 点击进入运行详情。

不得使用 Mock 数据冒充真实运行。

## 第三阶段：Trace Detail

开发 `/traces/:runId` 页面。

展示：

- Run 基本信息及版本。
- Span 层级和真实执行时间。
- 节点成功、失败、跳过、重试等状态。
- 节点耗时和整体耗时。
- 失败节点突出显示。
- 点击节点打开 Inspector。

## 第四阶段：Node Inspector

展示当前 Span 的：

- 输入输出摘要或受控快照。
- Event 时间线。
- 错误代码与错误详情。
- LLM 模型和 Prompt 版本（如有）。
- Evidence ID、候选洞察、拒绝规则及原因（如已采集）。
- 关联 RunManifest。

没有采集到的字段明确标记为不可用，不推断、不伪造。

## 第五阶段：安全与稳定性

- 复用现有权限机制。
- 敏感数据默认脱敏。
- 不暴露密钥和完整用户数据。
- 不影响业务工作流。
- 处理历史缺失数据。
- 保证页面刷新后可重新加载。
- 允许手动刷新，轮询作为可选增强。

## 第六阶段：验收

使用真实后端运行记录验证：

1. 成功 Run 可以完整展示。
2. Failed Run 可以定位失败 Span。
3. Partial Run 不被误判为成功。
4. Inspector 能正确显示实际采集的诊断信息。
5. 运行数据与数据库记录一致。
6. 无权限访问被拒绝。
7. Admin 构建及现有后端测试通过。

交付代码变更清单、真实运行示例、测试结果、未采集字段和剩余问题。

不要在本轮加入版本评测、Prompt 编辑或自动修复功能。
