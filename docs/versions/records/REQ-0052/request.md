# InsightFlow Admin — Prompt Registry V1.0

## 目标

基于已完成的 Prompt Registry V0.1，实现 Prompt 版本管理的只读 Admin 页面。

重点支持三个 LLM 节点的模板历史、版本详情、文本 Diff 和调用记录关联。

## 第一阶段：审计现有 API

检查 Registry V0.1 的数据库、服务层、权限控制和 Trace 关联。

优先复用已有契约，确认是否需要补充只读查询 API。

不得建立第二套 Prompt 快照存储。

## 第二阶段：Prompt 列表与历史

支持：

- 按 Intent Parser、Analysis Planner、Insight Generator 筛选。
- 查看每个节点的 Prompt 模板。
- 查看真实存在的历史快照。
- 展示版本号、哈希、创建时间、来源 Commit。
- 区分当前已登记版本与历史版本。
- 没有历史快照时显示明确空状态，不生成虚假历史。

## 第三阶段：版本详情与 Diff

支持：

- 查看 System、固定 User 模板、重试指令和其他已登记的固定片段。
- 查看模板变量和组合定义。
- 选择两个实际存在的快照进行文本 Diff。
- 对比内容哈希及变更元信息。
- 支持复制模板内容。
- 明确标注缺失或不可恢复的历史内容。

## 第四阶段：调用记录关联

支持：

- 从 Prompt 版本查看关联的 LLM 调用。
- 查看调用时间、节点、重试序号、状态和模型。
- 从现有 Report Trace 跳转至 Prompt 版本详情。
- 对 Intent、Planner 尚无持久 Trace Run 的情况，允许通过调用记录查询，但不能伪造 Run 关联。
- 完整请求快照只允许授权人员查看，默认展示脱敏摘要。

## 第五阶段：测试与验收

至少覆盖：

1. 三个节点均能读取真实快照。
2. 只有一个版本时正确展示。
3. 两个版本存在时 Diff 准确。
4. 不同动态请求不会被错误识别为模板修改。
5. 无权限用户无法读取敏感快照。
6. 历史缺失内容显示 unavailable。
7. 关联调用和 Trace 跳转准确。
8. 页面刷新、分页、空状态和 API 异常处理正常。
9. 现有前后端测试不退化。

## 边界

本轮不实现在线编辑 Prompt、Playground、自动评测或一键发布。

不修改三个 LLM 节点的业务逻辑，不修改现有 Prompt 内容。

交付修改文件清单、真实 API 示例、页面截图或操作说明、测试结果及已知限制。
