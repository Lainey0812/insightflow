# Trace 详情瀑布流

REQ-0125，关联 REQ-0124。宏观列表仍是 `/traces`。每条记录进入 `/traces/:runId`。

详情主区域按 60% / 40% 分栏。左侧是这条任务已保存的 workflow，按开始时间和耗时画成瀑布流。条形不估算缺失时间。同一会话若另有 workflow 根记录，会把根上尚未出现在当前记录里的节点按原顺序补进同一条瀑布流，不复制已有 span。报告记录投影出来的 span 仍保留 workflow 根的 run_id，前端不再因此把整页判成加载失败。

右侧是当前点击节点。状态、输入、输出同时展示，不再藏在页签后面。原始 prompt 和模型原文仍然不写入 Trace；没有采集的字段显示未采集。Token 不写成 0。

`hitl`、`analysis_engine`、`chart_builder` 没有归进 LLM、Tool 或 Condition，瀑布流上显示未归类。

浏览器打开一条同时带准备节点和报告节点的记录。瀑布流有 14 个节点，左右栏宽度约为 755px 和 503px。点「洞察生成」后，右侧标题变为洞察生成，并显示状态、输入、输出。
