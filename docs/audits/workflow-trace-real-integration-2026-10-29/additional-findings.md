# 补充核对与真实验证状态

## 数据发送范围（按实际代码）

- Intent 当前 build_dataset_context 只生成数据集名称、行数、列名、字段 ID 和物理/逻辑类型，不发送样本行。
- Planner 使用结构化意图、约束、字段类型和质量计数、能力说明；planner/context.py 明确不含原始记录或样本。
- Report 会发送执行后选择的 Evidence、任务、目标和统计范围。这些是实际数据的聚合/派生信息，仍属于向外部模型服务发送业务相关内容。
- 不发送完整 CSV。不因是本地前台就忽略外部模型服务目的地。

## 额外缺口

1. Report 输入核验与 Chart Builder 没有独立 Span；这些位置失败可能出现 failed Run 而没有对应 failed Span。不能保证任意失败都定位到具体节点。
2. report_generations 以 execution_id 为主键保存最新尝试状态，重试会替换当前行；成功报告不可变，旧报告尝试的元数据主要依靠各自 TraceRun 留存。若当时 Trace 写入失败，则历史失败尝试可能缺失，不能宣称完整历史。
3. LLMCallRecord 不存完整响应正文，Response 哈希及受控投影不能逆向恢复候选原文。排错需要后续明确受控输出快照策略，不能用重新调用模型替代历史请求/输出。
4. 本机测试免登录是先前用户明确要求的环境配置，不等于已经完成多用户权限系统。
