# InsightFlow 典型测试集 V1

日期：2026-11-09。需求：REQ-0108。包含15个测试用例、6份可直接上传的合成CSV、逐例需求与预期、结果记录模板。数据不来自任何真实客户或个人。

## 下次直接使用

1. 打开 [逐例测试手册](CASES.md)，从 TC01 开始。
2. 上传该例指定的 `data/` 文件。默认表头行1，TC07明确使用6。
3. 复制需求，按步骤操作，审核实际计划后再批准。不要跳过HITL。
4. 将 `results-template.csv` 复制到新的日期目录，再填写结果；原模板和本套件不要覆盖。
5. 在Admin按实际 `workflow_id` 查节点、耗时、结果、错误及调用快照。不要复用历史Run作为本次结果。

现有冻结产品验收和历史评测继续保留，本套件不替换它们。V1是显式测试集，不属于独立未见集；后续拿它调优Prompt后，不能再声称它是未见评测。

## 统一验收规则

- 不要求LLM生成固定文案、固定task_id、固定字段ID或固定任务数；检查实际目标、约束和可执行步骤是否等价。
- 数值基准来自合成文件的独立计算。若未要求排序，按类别匹配结果，不以数组顺序判失败。
- 执行前必须有当前版本的有效批准；修改或删除后必须重新校验，旧审批不得批准新版本。
- Planner遇到缺字段或能力时，不得发明字段、删除核心任务或换成无关指标。明确澄清可以接受；静默假设不接受。
- 报告中的数值必须有真实计算证据；正确计算结果不等于报告解释已经通过人工业务评审。
- 零结果、模型失败、部分业务成功和Trace缺失分开记录。不要用“是否生成报告”作为唯一通过指标。
- 节点仅展示实际采集Span；跨业务库、Trace库、Registry的引用必须一致。Prompt版本必须来自实际Call快照。
- TC13没有非核心方向可删除时，该分支记not_applicable，不为了测试删除功能强行删除核心目标。
- 记录状态使用：not_run、passed、failed、blocked、not_applicable。业务自身complete/partial/failed/unavailable另写实际结果，不与测试状态混用。

## 离线自检

从项目根目录运行：

```sh
.venv/bin/python docs/testing/typical-suite-v1-2026-11-09/verify_suite.py
```

该命令只读取测试文件，检查15例定义、6份数据、数值基准和SHA256，不启动产品、不调用LLM、不修改数据库。`build_suite.py`是一次性生成来源，使用独占写入防止覆盖；下次测试不要重新运行生成器。

## 版本与结果保存

每轮新建 `docs/testing/runs/<日期-批次>/`，复制结果模板，在该轮目录保存模型/Prompt快照ID、步骤、实际输出、失败原因和截图。不得把not_run直接改成passed而未执行，也不得将故障注入Provider当作真实LLM评测。后续修正本套件需新增V2目录并关联需求，旧V1和失败记录保留。
