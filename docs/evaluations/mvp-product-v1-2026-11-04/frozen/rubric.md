# MVP 产品验收 V1：冻结评分规则

日期：2026-11-04。需求 REQ-0089。此规则先于本轮任何真实模型运行冻结，不根据运行结果放宽。后续变更必须另建版本并保留本版。

## 范围与数据

本轮包含 20 个业务/故障场景：四类主题共 16 个真实 LLM 场景，其中 12 个 core、4 个 holdout；另有 4 个故障场景。故障使用受控自动化测试，必须与真实模型结果分开统计。参数化测试数量不等同于场景数量。

四份 CSV 均为明确标注的合成验收数据，没有真实客户、求职者或员工资料。小样本用于发现产品缺口，不代表生产准确率。源数据和 Gold 预期在 cases.json 冻结。测试 runner 不得调用生产操作内核生成基准答案。

holdout 在 core 完成后运行。在运行 holdout 前后均不得据其输出修改 Prompt、业务规则、模型参数或本评分规则；本轮仅定义“新建且未用于本轮调优”，不能声称对预训练模型绝对未见。

## 两层计算检查

第一层，用户目标独立基准：直接从 CSV 用独立 Pandas 筛选、聚合、排序产生 expected，不读取 Planner 的操作链作为业务答案。按真实字段身份和指标函数匹配计划；检查显式筛选范围、维度、统计口径、排序与 Top N。不得只用“最终数字碰巧相等”证明约束忠实。

第二层，执行一致性：对计划中每个受控步骤作独立参考计算，对比实际持久化完整结果。第二层通过不能替代第一层，因为错误计划也可能被正确执行。

开放探索没有预先唯一正确计划；必须由审阅者逐任务判断目标相关性、重复性、优先级及口径。可以自动检验计算和引用，但不能把自动检查称为业务价值验收。

## 硬失败条件

任一项发生，本例不得完整通过，不可由平均分抵消：

1. 未经有效批准执行，或执行错误数据集/计划版本。
2. 显式时间、筛选、指标、排序、Top N、排除或禁止边界被静默改变。
3. 计算与独立基准不一致，或未经证据计算的新数值进入报告。
4. 无依据因果、利润/经营判断，或将 Top N 当作总体。
5. 无证据的确定性结论、无效 evidence_refs、失败任务伪装成功。

测试 runner 在审批前发现明确目标或范围错误时必须停止该例审批，保存候选、原因和错误计划，不为了完成链路执行已知错误计划。不自动删除不安全任务，不替用户解决未确认的不确定性。

## A–G 评分

每维 0/1/2，必须记录理由与引用。未审阅使用 null，不得补成满分。

| 维度 | 0 | 1 | 2 |
| --- | --- | --- | --- |
| A 事实准确性（硬门槛） | 错误事实/计算/口径 | 未发现错误但缺少足够核验材料 | 可核验关键事实均与独立计算及证据一致 |
| B 重要证据利用 | 核心证据遗漏 | 使用部分核心证据 | 覆盖目标相关核心证据，没有堆砌 |
| C 洞察深度 | 无有效发现 | 主要复述单个数值 | 有证据支持的比较或结构发现；单指标问题允许直接明确回答 |
| D 业务相关性 | 偏离核心目标 | 部分回答或包含无关任务 | 覆盖本例核心问题，不增加用户未要求的核心目标 |
| E 建议关联性 | 空泛、无依据或写成已完成 | 与主题相关但不够具体 | 对应实际发现且可验证；单纯统计无需强行提出建议 |
| F 用户表达 | 技术化或易误解 | 基本能读懂，范围/局限不够清楚 | 目标、范围、发现、下一步和局限清晰 |
| G 安全边界（硬门槛） | 无依据断言/总体误读/违禁 | 未发现越界但材料不足 | 核验后未发现边界违规，失败和不确定性清楚呈现 |

A/G 人工语义审阅不能由正则或模型自报代替。本轮执行者的审阅标记为 agent_review，不冒充目标用户复核。

## 结果分类与分母

- complete：达到本例预期，全部硬门槛满足，必要核验完成；预期阻断/澄清场景正确阻断或恢复也可通过，但必须单列，不能算报告交付成功。
- partial：有有效结果但目标/报告仅部分覆盖，或明确存在未完成内容。
- failed：触发硬失败、应该阻断却放行、应该澄清却忽略，或产品流程出错。
- unavailable：真实模型/网络/Registry/依赖不可用，没有足够输出评价业务质量。
- pending_review：自动检查已完成但必要语义/用户审阅未完成，不能算 complete。

分别报告调用成功率、准备成功率、审批可达率、报告完整/部分/失败、约束检查通过率、完整请求通过率、硬失败数量、core/holdout 分组；每项显示实际分子分母。不能用 Schema 合法率或自动化测试通过率代替产品成功率。

真实模型超时、HTTP 错误、Schema 拒绝都保留。程序自身的验收工具错误也必须保留，纠正时以新 run 编号运行，不覆盖原输出，不归罪产品。

## 用户试用资格

完成产品验收仍不等于普通业务人员能独立使用。另邀 3–5 位真实目标用户，每人完成明确目标及开放探索任务。记录独立完成、帮助次数、各阶段耗时、审批理解、报告复述与证据定位。未实际组织前全部标记待开展，不制造用户评价。

后续 HITL 自然语言修订是独立开发阶段，应依据本轮 Bad Case 冻结最小范围后实施，不在验收过程中改变基线。
