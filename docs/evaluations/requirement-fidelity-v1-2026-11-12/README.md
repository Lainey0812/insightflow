# 需求保真评测 v1

日期：2026-11-12。需求：REQ-0137。检查用户原始需求里的目标和约束有没有经过意图解析、计划、校验，并被分析引擎实际执行。

计划版本一致、计算结果自洽、报告可以回溯，都不能代替这一检查。用户要求排除某个取值时，引擎结果仍出现该取值，即判定引擎没有执行该条件。

## 四段

每条冻结义务单独记四段，段之间不互相补判：

- Intent：约束进入了已保存的结构化约束。只出现在业务目标正文里，记为 `prose_only`，不算结构化落实。
- Planner：规划结果里，每个应执行的任务在聚合前带有对应筛选、年份、指标或维度。
- Validator：批准或保存后的计划仍带有该条件。规划结果里有、批准计划里没有，记为 `dropped_after_planning`。
- Engine：执行日志里的对应步骤实际跑过。排除条件还要核对已保存结果：被排除的取值不得出现，同时要求保留的分组取值仍在。做不到这两点时，即使步骤编号存在，也判引擎未执行该条件。

没有执行记录时，Engine 记为 `not_observed`，不记成通过。`不排除` 不是排除。`只看` 某个值不是排除该值。

## 本版范围

冻结义务目前只有典型套件 TC02。查询原文的 SHA-256 与 `obligations.json` 不一致时，结果为 `query_mismatch`，不用另一句需求套用这组义务。TC03–TC15 尚未列入，不能把本文件说成全套件保真结果。

纳入条件、年份、指标和维度时，引擎只证明对应步骤跑过，不重新计算数字。排除条件额外核对结果取值。原有回归的数值基准仍然单独使用，不写入本评分，也不被本评分覆盖。

评分不调用模型，不修改意图、计划、校验或执行。
