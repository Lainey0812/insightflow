## 2. 校验规则前后对照

| 范围 | V1.1 问题 | 当前候选 |
| --- | --- | --- |
| 原子事实 | 新比较有算术检查，部分基础类型依赖 Builder | 对选中证据再次核对结果单元格、指标/单位、行、排名、差值、分子/分母；保留原比较算术校验 |
| 多证据 | 引用相同元组才能组合，但错误信息笼统 | 保留当前同指标组合契约，输出各引用绑定；不自动移除不合法辅证 |
| 否定边界 | 先删半句使“不代表…占比”变成正向敏感词 | 完整已支持边界优先检查；保留原文，记录校验视图规范化；不是全局放行“不能/是否/可能” |
| 数量引用 | 两个时间点/服务组/批次、P0、中文 Top 3 边界误拦 | 来源维度与比较对象校验；已批准 Top N 参数及真实任务标签；数字事实仍不得仅凭数值相同而放行 |
| 稳定性 | 首末相同可被错误解释成期间稳定 | 依据真实时间维度检查，不因改选 ranking/difference 就绕过守卫；没有期间稳定证据仍拒绝 |
| 强度/原因 | 词规则覆盖有限 | 继续拒绝无阈值“绝大部分”等和无依据因果/经营断言；剩余误拦/漏检明确记录，不宣称完整语义验证 |
| 候选隔离 | 能部分保留，但只返回通用首错 | 保留合法候选并 partial；全拒绝保留所有候选诊断；报告元数据不嵌入被拒绝的原断言，原文另存在评测记录 |
| 核心覆盖 | 主要依赖 task_id | 增加 P0 指标级覆盖；O03 只保住 hours 时明确 tasks 缺失并 partial，不降低已有核心任务守卫 |

三种情况明确分开：

1. **同指标比较**：现有多证据组合继续支持。
2. **跨指标事实并列**：工时、任务数量各自形成合法同指标 Insight，再并列进入一个报告；最终真实 O03 已做到。
3. **跨指标派生计算**：必须有明确验证的计算证据；当前 Draft 不支持把 hours 与 tasks 两个证据 ID 拼成效率或混合差值。没有永久宣布所有跨指标业务分析非法。

`claims.py` 的职责是检查结构化数据，不解释任意句子。自由文本层仍为有限、保守的护栏，存在语言变体误拦与业务边界漏检。安全规范化只改变检查视图，原候选文本没有被静默删掉再冒充通过；完整规则记录在 `execution_metadata.text_validation`。不安全候选继续拒绝，没有模板兜底或额外 LLM 修复循环。

## 3. fact / finding 与展示来源

- `fact`：紧凑的已验证操作数记录，包括证据 ID、指标、对象、原值、差额/分母等，供核对详情使用。
- `finding`：由结构化证据确定性组合的可读发现；相同排名/极值去重；relative_lead 已表达的同对象差额不重复粘贴。
- `implication`：LLM 的待验证业务解释；明确不等于已完成语义事实验证。
- `recommendation`：尚未执行的下一步动作，主区集中展示一次。

摘要保留目标、数据范围与结果状态，不再整段复制 finding。页面和 HTML 使用同一保存报告与 Presentation，不另生成 V001 等第二套业务结论。KPI/证据展开中为追溯而再次出现指标，不等于默认重复一整段发现。

旧无 generation 的报告继续显式使用 legacy v1 分支；旧 `evidence-composition-v1.1` 报告继续使用已有的 saved-insights 来源，新实现不静默切换它们到旧 V 证据模板。原报告 JSON 没有迁移或改写。
