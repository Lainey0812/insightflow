## 固定评测集

文件：[backend/evaluation/intent_cases.json](../backend/evaluation/intent_cases.json)。40 条固定输入，销售订单、AI 产品经理招聘、客服工单、项目任务各 10 条，其中销售包含一份恶意字段名/文件名的元数据变体。全部是工程合成数据，不打开用户上传的个人工作簿。

覆盖：明确目标、开放探索、模糊请求、多个筛选条件、明确/未明确/否定的决策目的、可延后的统计口径、必要筛选信息缺失、数据主题不匹配、相对时间、样本中的无关指令及元数据注入。

预期结果包括 analysis_mode、next_action、decision_goal、按类别保留的约束片段、必要的不确定性动作。标签依据用户规格与工程规则编写；文件中的 human_reviewed=false 表示尚未由业务负责人逐条复核。没有把 AI 编写的全部参考答案宣称为人工已确认的金标准。用户明确列出的示例用 user_spec_example 标记。

格式错误、模型超时等是可控故障注入，不要求真实模型故意生成坏 JSON；这些由单元测试验证，不计作真实模型语义样本。

## 运行真实评测

在同一终端配置模型后运行：

```bash
cd backend
../.venv/bin/python scripts/evaluate_intent.py --live
# 需要重复稳定性观察时，每个样本最多重复 3 轮：
../.venv/bin/python scripts/evaluate_intent.py --live --repeats 3 --output ../docs/intent-live-repeat-evaluation.json
```

默认输出 docs/intent-live-evaluation.json，逐项写入进度，包含模型名、Prompt 版本、数据集版本与摘要、重复轮次、期望、实际输出、错误阶段、请求次数和失败原因。只发送轻量元数据和合成需求，样本行始终为空。会调用配置模型，可能产生费用；不加 --live 不调用，未配置以退出码 2 留下 blocked 记录。

脚本无需在 PYTHONPATH 中手动加入工程目录。模型 Key 只从现有环境变量读取，不写入测试数据、输出文件、错误内容或日志。需要保留多轮记录时使用 --output 指定不同文件。

## 指标口径

| 指标 | 分子 / 分母 | 目标 |
| --- | --- | --- |
| 对外 Schema 合法率 | 合法返回 / 实际返回；没有返回时为 null | 100% |
| 模式准确率 | 模式正确样本 / 所有已测试样本，模型错误也计入分母 | ≥90% |
| 约束召回率 | 正确类别中找到的预期原话片段 / 所有明确约束片段 | ≥95% |
| 不应编造的决策目标 | 预期 decision_goal=null 时的非空返回数量 | 0 |
| 阻断问题召回率 | 对应 clarify 返回 / 应当 clarify 的样本数，错误不算识别成功 | ≥95% |

约束匹配只做 NFKC 和空白规范化后的片段比较，要求类别正确。结果同时输出每项判定、完整合法意图、失败案例、case_pass_rate 和各指标分母；不会通过排除错误响应抬高模式或约束得分。无返回不标成 100% 合法，无样本不标成“0 个编造已验证”。

engineering_targets_met 只比较上述数值目标，并要求所有样本都有有效返回。acceptance_passed 还要求参考标签已完成人工复核。解释性文字、分析对象是否恰当、问题是否最关键、否定语义与推断是否合理仍需人工审阅，脚本明确输出 prose_semantics_verified=false / human_review_required=true。片段匹配不是通用语义证明。

## 当前 Bad Case 分析

10 个整例未通过，全部涉及约束未按预期原话片段和类别保留。未删除样本、修改参考标签或放宽匹配来提高得分。

| 案例 | 实际表现 | 判断与影响 |
| --- | --- | --- |
| S04 / C04 / P04 | “排名”保存在 metric_requirements 的完整短语内，analysis_limits 只有 Top N | 原话并未完全丢失，但分类与约定不一致，按现行类别评分失败；后续 Planner 不应只读单一类别忽略原话。 |
| S09 / C10 | 保存“不限定均值或中位数”等说明，缺少销售额 / 响应时长这一指标约束 | 目标中虽有指标，constraints 未完整保留显式要求。 |
| R01 / C07 | 岗位数量 / 响应时长在目标中出现，metric_requirements 为空 | C07 正确提出补充客户的问题，但澄清状态不能丢失已有的指标需求。 |
| C06 | 仅保留“数量”，未保留“工单数量” | 属于片段完整性失败；结合目标能理解含义，不应描述成完全没有识别计数意图。 |
| R10 | “没有指定均值或中位数”变成约束“均值或中位数”，同时缺少薪资指标 | 人工检查发现否定信息丢失；原话子串可追溯校验并不能阻止此类语义反转。 |
| P10 | 把“不要替我推断要裁员”放入指标约束，任务数量缺失 | 决策目标保持 null，但否定限制分类错误。 |

额外审阅：S04 在 business_goal 中加入“订单或品类”等用户未明确的候选粒度，未记录对应不确定性；这属于自动评分之外的解释风险。S08 / C08 正确发现销售 / 工单数据与招聘薪资需求不匹配并要求澄清；S10 恶意元数据变体中仍保留用户的地区销售比较需求，未执行元数据中的指令。不能据单个变体推断已解决所有提示注入。

建议下一轮先完善独立 Prompt 对指标、排序、否定表达的分类与完整保留规则，再使用相同固定集对比；不得以关键词补齐未经模型理解的成功结果掩盖缺陷。本轮只完成复测和必要兼容修复，未修改 Prompt 或扩展其他业务模块。

已完成的工程故障验证（受控测试，不属于真实模型质量评测）：

| 故障输入 | 实际处理 | 目的 |
| --- | --- | --- |
| 非 JSON、重复键、NaN、非法 Unicode | json 阶段拒绝，有限重试，耗尽返回 LLM_INVALID_JSON | 防止坏输出进入下游 |
| 非法枚举、缺失字段、错误 null、额外任务字段 | schema 阶段拒绝 | 保持对外契约 |
| undetermined + proceed、defer + before_planning、clarify 无问题 | semantic 阶段拒绝 | 保持暂停/继续规则一致 |
| 模型自行补充“2026年”、用户未要求的城市或决策 | 原话校验拒绝 | 防止字段和模型推测变成用户约束 |
| 数据行中包含忽略规则或私人邮箱 | 不发送任何样本行 | 缩小隐私和注入面 |
| 恶意字段名 / 文件名 | 仍作为 JSON 数据，独立系统规则与严格输出契约 | 不把元数据提升为系统指令；本轮 S10 通过，仍不代表所有注入均可防御 |
| 未配置、超时、认证/连接错误 | 明确错误，不造成功结果 | 保障失败可见 |

## 实测后的 Bad Case 处理顺序

1. 查看输出记录中 bad_cases 的 case_id、expected、result 或 error、failures。
2. 区分语义误判、遗漏约束、过度澄清、编造决策与调用/格式失败。
3. 先复核参考标签，尤其是数据主题不匹配是否应澄清、可后定口径是否应 defer，避免把有争议标签当模型错误。
4. 调整独立 Prompt 并升级版本，保留原固定集，再跑相同模型和配置；不得删除失败样本来制造通过率。
