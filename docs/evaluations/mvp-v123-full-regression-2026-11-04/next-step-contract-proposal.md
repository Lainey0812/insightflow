# 下一步最小建议：Report Draft V2 的职责隔离

这是基于本轮实测的待评审方案，不是已上线能力；本轮没有实现或切换契约。

## 为什么不继续扩写正则

当前 Draft 把证据选择、数据事实复述、业务解释、因果推测和下一步建议混在自由文本里。最终事实已经由代码组合，但模型仍重复“最高”“一个月份”等信息，导致合法事实与格式守卫冲突。另一方面，只要避开已知触发词，无依据市场、客户行为或人员配置解释仍能进入报告。

放宽守卫会增加信任风险，继续逐句加白名单又不能稳定覆盖自然表达。应改变生成层职责，而非在页面上用模板替换失败输出或假装模型成功。

## 最小内部契约

保持公开 AnalysisReport / Insight / ChartSpec 与页面契约，继续使用单 LLM 和现有 Provider。只调整内部 Draft 与确定性物化过程：

| 内容 | 内部输出与校验 | 用户展示 |
| --- | --- | --- |
| 事实与比较 | 模型选择 Evidence ID、同口径组合和 finding_type；代码验证与计算表达 | 真实数值、排名、差异、分母和范围 |
| 核心相关性 | 引用当前任务/核心需求及受控用途，不生成新的原因或经营效果断言 | 回答哪项问题、适用范围、尚不能解释什么 |
| 下一步建议 | 受控建议类型 + 当前真实字段引用，例如比较分组结构、核查记录完整性；数据类型与必要字段确定性核对 | 使用实际字段名称描述可进一步核查的方向，并说明尚未分析 |
| 数据局限 | 引用已验证 limitation ID | 由确定性代码呈现数据质量、覆盖及失败边界 |

不在 Report 里创建 AnalysisTask、执行操作链或启动分析。建议只是后续可考虑的业务方向；用户提出新需求后仍需经过既有 Planner 和 HITL。缺少必要数据时不编造字段或承诺现有能力。

MVP 先不让模型输出未经证据支持的自由原因解释。若后续产品需要业务假设，应另行明确支持材料、显示边界与审核规则；不能仅靠给正文加“可能”或“待验证”前缀放行。

## 与规则兜底的区别

这是明示的生成契约变更：模型负责选择真实证据和后续方向，代码负责把已验证结构表达为可读内容。保存实际模型选择、原始输出与拒绝记录，不能把非法选择自动替换成另一条“成功洞察”。模型失败、引用错误或核心覆盖不足仍按既有失败/部分状态处理。

即便字段和引用合法，也不保证业务建议有价值；必须继续用冻结场景和新的独立场景评测相关性、证据利用和可读性，不能用结构通过率代替产品验收。

## 预计改动

主要涉及内部 Draft Schema、Report Prompt/动态输出 Schema、物化与建议绑定校验，以及相关测试。复用 Evidence Builder、Registry、Report 持久化和 Trace，不修改 Engine、HITL 审批业务、Session 状态权威或 Workflow Root 架构。

历史报告继续按保存内容读取。历史 Draft、Prompt 和调用快照保留；新版本以新 Prompt/内部 Schema 版本登记，不覆盖旧内容。公开报告仍可预览、下载和追溯。

## 准入与验证

先冻结 V2 内部输出、合法/非法建议样本与拒绝理由，再实施。重点验证：无字段不能提出看似可执行的方向；不能把客服建议说成销售建议；不能复述/计算自由数值；不能为填条数遗漏 P0；无证据不能编造原因；不能以规则伪造 LLM 成功。完成自动化后，同输入复评并增加新独立业务样本，单列真实用户理解测试。
