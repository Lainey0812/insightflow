# 条件值复核：运行后发现的验收工具盲点

本记录是本轮模型运行完成后追加的工具修正说明，不冒充运行前冻结评分器。原 Gold、评分规则、原 result.json 和旧 goal-oracle.json 均不覆盖。

P02 的冻结要求明确为 `项目 ne 丙`。本轮 Planner 输出 `项目 ne 丙项目`。因为原合成 CSV 中丙项目没有已完成任务，状态筛选之后两种条件返回相同行集和合计。原验收器根据行集、数值和操作顺序把 goal_plan 记为 true；这个自动结论不足以证明过滤值忠实。

产品审批层将该计划标记为不匹配并拒绝，这次拒绝是正确的，不应被归类为审批误拦截。

新增独立工具 `backend/scripts/mvp_plan_scope_audit.py` 从既有冻结 Gold 直接核对字段、操作符和条件字面值。支持已验证的 eq/in(单值)、ne/not_in(单值)非空语义等价；多值集合按精确成员核对；年份只证明当前明确支持的完整年范围或真实年份派生。未支持的编码返回未证明，不声称通用 SQL 等价性。

本次只修改评测工具与测试，不修改产品审批、Planner、Engine 或业务状态。新增六项测试覆盖错误冗余条件、等价单值集合、多值额外排除、标量类型、无请求筛选和不完整年份边界，全部通过。

结果另存 scope-literal-recheck.json；原自动 goal_plan=true 保留，人工结论明确纠正。不能改变本次分母、修改 Gold 值或将错误值补成用户“可能的意思”。未来回归应纳入该项检查；不能再仅凭 Pandas 数字相同认定约束继承完整。
